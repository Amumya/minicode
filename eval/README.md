# eval

评测放在这里。现在还是空的，任务集和判定器都没写。

之所以单独建一个目录，是因为这个项目最重要的事情就是"说得出数字，而且别人能核对"。
所以定几条规矩，写在前面：

1. 每个数字都要有对应的原始运行记录，放在 `runs/` 里。`eval/runs/` 故意没有加进
   `.gitignore`。哪条数字找不到记录，那条就作废。
2. 每条结果要写清楚条件：模型是哪个、样本量多少、改了什么变量、什么时候跑的。
   不带条件的数字不算数。
3. 判定器本身也要测。判定器有 bug 的话指标会乱飘，而且不会报错。
4. 样本量少就写少。两个样本跑出来的差别，只能说"这个变量影响挺大，值得多跑几个"，
   不能写成翻了一倍。
5. 指标撞到天花板的要标出来。满分基线证明不了任何机制有用。

目录大概长这样：

```
eval/
├── tasks/     任务定义
├── sandbox/   任务用的起始代码，每次跑之前重置
├── runs/      运行记录
└── README.md
```
