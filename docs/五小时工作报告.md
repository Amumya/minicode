## 三、现在三种入口都能用

```powershell
# 1) 命令行
minicode run "数一下 src 下有几个 py 文件" --plan --skills --compact --subagent

# 2) HTTP + SSE
minicode serve --port 8765
curl.exe -sN http://127.0.0.1:8765/runs/<id>/events

# 3) 浏览器
http://127.0.0.1:8765/
```

新加的开关：

| 开关 | 作用 |
|---|---|
| `--plan` | 挂上 `todo_write`，并把"多步任务先写清单"写进提示词 |
| `--skills [DIR]` | 挂上 `load_skill`，目录进提示词 |
| `--compact` | 开启上下文压缩 |
| `--subagent` | 挂上 `task`，可派子代理 |
| `--no-python-hint` | 对照实验用：不告诉 agent 该用哪个解释器 |

服务端的 `POST /runs` 也支持 `plan` / `skills` / `compact` 三个布尔开关。

## 五、这五小时抓到的四个真问题

### ① 最严重：隐藏测试从来没被执行过

- **症状**：所有任务都能过，数字很漂亮
- **根因**：隐藏测试叫 `hidden_*.py`，而 pytest 只收集 `test_*.py`。判定器跑 `pytest -q`（不带路径），
  只收集到可见测试 —— **所谓"隐藏测试判定"一直在重跑可见测试**
- **影响**：阶段 D 那批沙箱数字**全部作废**
- **修法**：拷进工作区时改名成 `test_hidden_*.py`（第一次试"显式传路径"没用，pytest 对显式路径也套规则）
- **防线**：新增 `eval/verify_tasks.py`，不跑模型几秒钟检查"起始代码下隐藏测试必须挂"

### ② 沙箱提示词漏了"用哪个 Python"

- **症状**：单次任务从 ~15 秒涨到 73–87 秒
- **根因**：工作区默认 `python` 没装 pytest，agent 于是 `pip install pytest`，而 PyPI 不通，卡满 60 秒超时
- **更根本**：我在 CLI 里加了"用哪个解释器"的提示，**却忘了加在沙箱的系统提示词里**
- **修法**：两边共用同一个 `default_system()`

### ③ 压缩剪枝会留下孤立的 tool_result

- **症状**：单元测试报"压缩后出现了没有 tool_use 的 tool_result"
- **根因**：剪枝切点算成 `i+1`，只删了 assistant，把它的 tool_result 留下了
- **后果**：这种对话结构非法，下一次请求直接 400，而报错跟压缩毫无关系
- **修法**：切点改成 `i+2`，删就删整对

### ④ run 列表排序在时间戳并列时会乱

- **症状**：`test_all_returns_newest_first` 偶发失败
- **根因**：这台机器上 `time.time()` 连续三次返回**完全相同的值**（计时器粒度约 15ms），
  zset 分数并列后排序退化成按 id 字典序
- **修法**：改用自增序号当排序依据

## 七、这次做下来，三条方法论教训

1. **判定器必须自己被测。** 一个错的判定器不会报错，只会给出好看的数。这次的症状就是"全部通过"。
   现在有 `verify_tasks.py` 守这一条。
2. **用桩做的检查，只能证明"假设的输入被正确处理"。** 上一轮 `end` 事件的 bug 就是这么漏掉的：
   我在桩里用了"正确形状"，而真实服务端发的是错的。要证明端到端一致，得拿真实输出当夹具。
3. **指标定义错了，数字会看起来完全合理，然后一路错下去。** 这轮和上一轮各踩了一次
   （"工具失败率"把测试红算成失败；"沙箱通过率"其实在跑可见测试）。
   **先问"这个数在数什么"，再问"它是多少"。**
