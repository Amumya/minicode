# 面试怎么讲这个项目

这份是给你自己看的：怎么用 3 分钟把这个项目讲清楚，以及被追问时怎么答。
**每个答案都能指到仓库里的文件和数字** —— 这是它和"我做了个 demo"最大的区别。

---

## 一、3 分钟演示脚本

### 第 0 步：开场一句话（15 秒）

> "我写了一个编码智能体，但重心不在主循环 —— 那个已经有 opencode、codex、gemini-cli 这些了。
> 我做的是**治理层和评测**：权限怎么判、每一步怎么观测、以及怎么证明它真的有用。"

**别这样说**："我写了一个类似 Claude Code 的东西。"—— 那句话会让你被拿去和 21 万星的项目比。

### 第 1 步：跑一个任务，看事件流（40 秒）

```powershell
minicode run "数一下 src 下有几个 py 文件" --save
```

指给他们看输出里的：

- **每一步都是一条结构化事件**（`model_call` / `tool_call` / `denied` / `finish`）
- **工具调用带退出码**：`[exit=0]`。这是刻意的 —— 没有退出码，命令失败在模型眼里和成功没区别
- 令牌和步数都记下来了，指标是从事件算的，不是从日志里正则抠的

### 第 2 步：展示治理层（40 秒）

```powershell
minicode run "随便做点什么" --plan --skills --compact --subagent
```

- `--plan` → 它有 `todo_write`，多步任务先写清单
- `--skills` → 技能目录进提示词，全文按需 `load_skill`（**目录只占正文的 21.8%**）
- `--compact` → 大工具输出落盘，省 45% 输入 token
- `--subagent` → 派子代理，父代理只拿结论（实测父代理 2 步 / 526 token）

**关键一句**："这些能力都是挂在钩子上的，主循环本身没为它们改过。"

### 第 3 步：亮数字（40 秒）

打开 `README.md` 最上面那张表。挑三个讲：

| 讲哪个 | 数字 | 一句话解释 |
|---|---|---|
| 权限判定 | 拦截率 **56.2% → 100%**，误报 **33.3% → 0%** | 子串黑名单换成"分词 + 参数判定" |
| 压缩 | 输入 token **−45%**，完成 3/3 | 而且我发现阈值设太大（12000）会一次都不触发，等于没开 |
| 沙箱 | 通过率 **83% → 92%**，但 token **+50%** | 加文件工具不是单向改进 |

### 第 4 步：讲那个 bug（30 秒）—— 这是最加分的一段

> "我的评测跑步者一开始判定所有任务都过。我没信，写了个自洽检查脚本，发现**隐藏测试从来没被执行过** ——
> 文件名是 `hidden_*.py`，而 pytest 只收集 `test_*.py`，所以我一直在重跑可见测试。
> 修好之后通过率才从 100% 掉到 83%。"

**为什么这段最加分**：它证明你会怀疑自己的指标，而且愿意为了一个"数字不好看"的真相去改工具。

## 二、高频追问与答法

### Q1 "这跟 opencode / Claude Code 有什么区别？"

> "功能面上没得比，我也不打算比。它们在**执行**这条线上已经很成熟了；我做的是**治理和度量**：
> 权限判定有多少误报、每一步花了多少、改动之后效果变好还是变差。
> 这个话题在我调研的时候是有公认空白的 —— 权限方向开源最高星只有二十几个，
> 轨迹级评测那个库七百多星且去年七月就不更新了。"

### Q2 "怎么证明你的 Agent 真的有用？"

> "分两层。第一层是沙箱任务：每个任务有隐藏测试，判定只认测试结果，不认它自己说做完了。
> 第二层是防作弊：权限层不让改测试文件（实测拦下 3 次），跑完再比对测试文件的哈希
> （实测抓到 1 次用 shell 绕过权限改测试的）。"

### Q3 "你这个评测样本量多少？"

**必须诚实**：

> "沙箱是 6 个任务 × 2 次重复，提示词实验每组 3 次。这个量级只能说方向，
> 说不出'提升几个百分点'。我在 README 里就是这么写的。"

如果对方追问"那结论可信吗"：

> "可信的部分是**方向**和**机制是否生效**：比如隐藏测试真的会挂、权限真的会拦、压缩真的省 token。
> 不可信的部分是具体幅度。"

### Q4 "为什么要自己写权限判定，不用现成的？"

> "找不到。我调研的时候，权限/策略引擎方向开源最高星的库只有 21 个 star。
> 而且现有 agent 的权限大多是子串黑名单 —— 我实测那玩意儿拦截率只有 56%，误报 33%。"

### Q5 "你的 Agent 会不会作弊？"

> "会，而且这是编码智能体最容易被忽略的坑：改测试、吞异常、硬编码返回值都能让测试变绿。
> 所以我把测试文件设成只读（权限层），判定用 agent 看不见的隐藏测试，
> 跑完还比对测试文件的哈希。现在的局限是：我做的是'能发现改了测试'，
> 还做不到'看出答案碰巧对了但逻辑是硬编码的'。"

### Q6 "上下文怎么管的？"

> "三层：大输出落盘（只留头尾和路径）、旧结果截断、消息太多时删掉最早的整对。
> 这里有一条硬约束 —— **绝不能把 tool_use 和它的 tool_result 拆开**，拆了下一次请求直接 400。
> 我第一版剪枝就踩了这个坑，切点算错，被自己写的不变式测试抓住。"

### Q7 "为什么要子代理？"

> "上下文隔离。子代理翻十个文件，父代理只拿到一句结论。
> 实测父代理 2 步 / 526 token 就拿到答案，子代理自己跑了 3 步 / 969 token。
> 另外我在工具集这一层就把递归断掉了 —— 子代理的工具列表里没有 `task`，不靠提示词约束。"

### Q8 "为什么用 SSE 不用 WebSocket？"

> "只需要服务端往客户端单向推。SSE 还能用 `curl` 直接验证，不用写客户端；
> 断线重连也能续推，因为事件都按序号存在 Redis 里。"

### Q9 "进程挂了怎么办？"

> "每轮结束存检查点，`POST /runs/{id}/resume` 从最后一个检查点接着跑。
> 实测：中断在第 1 步，杀掉服务进程重启后续跑，第 3 步完成。
> 检查点必须在**工具结果补齐之后**存，存早了对话结构非法，恢复后请求直接 400。"

### Q10 "这个项目最难的地方是什么？"

**别答"技术难"**，答这个：

> "最难的是**让数字可信**。我在这上面错了三次：
> 一次把'测试红'算成'工具失败'，一次隐藏测试根本没跑，一次剪枝破坏了对话结构。
> 三次都表现为'数字看起来完全合理'。所以我现在有个习惯：先问这个数在数什么，再问它是多少。"

## 三、绝对不要说的话

| 别说 | 为什么 |
|---|---|
| "我写了个类似 Cursor 的东西" | 立刻被拿去和大厂产品比，必输 |
| "准确率 100%" | 听起来假；而且你自己知道哪批数据是错的 |
| "参考了某某开源项目" | 可以承认**读过**，但要能说清"我改了什么、为什么改"（见工作报第二节的表格） |
| "用了 LangChain / LangGraph 做的" | 这个项目的卖点是自己搭的治理层，别把它说成框架的应用 |
| 具体数字说成"提升了一倍" | 只说方向 + 量级；样本量小的时候翻倍没意义 |
