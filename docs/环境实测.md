# 环境实测

2026-11-13 在这台 Windows 机器上测的。

这台机器网络比较特殊，而且隔一段时间就变（之前能用的通道后来不通了，
之前不通的反而通了）。写下来是为了下次跑不起来的时候先对一遍，别先去怀疑代码。

## 网络

| 目标 | 结果 | 怎么办 |
|---|---|---|
| github.com 网页 | 通，0.6 秒 | 能正常看 |
| api.github.com | 通，0.4 秒 | 推代码走这个 |
| codeload.github.com | 通，1.2 秒 | 要整仓就下 zip |
| git 协议到 github | 不通，Connection reset | `git push` 用不了 |
| ghproxy.net | 超时，已经挂了 | 之前配的改写已经删掉 |
| PyPI 清华镜像 | 超时 | — |
| PyPI 阿里云镜像 | 通，0.1 秒 | 本机 pip 用这个 |
| PyPI 官方 | 超时 | — |
| npm 官方 registry | 超时 | 前端那块暂时做不了 |
| npm 淘宝镜像 | 超时 | 同上 |

git 协议试过四种配置都不行（HTTP/1.1、放大 postBuffer、带 token 的 URL、默认），
全是 reset。所以推代码只能走 API，脚本在 `tools/push_to_github.py`。

npm 两个源都不通，所以原计划里写前端的那一步得等网络恢复，或者换台机器。

## 本机环境

| 项 | 版本 |
|---|---|
| Python | 3.12.10 |
| Node | v24.21.0（但装不了包） |
| git | 2.45.1（本地操作没问题，远端不行） |
| Docker | 没装 |
| anthropic | 1.11.0 |
| pytest | 9.2.0 |

`.venv` 是从上一版项目直接挪过来的，里面有 anthropic、python-dotenv、httpx、pydantic。
挪目录之后还能用，Windows 的 venv 是按 pyvenv.cfg 相对定位的，同版本同平台没问题。

pip 的镜像写在 `.venv\pip.ini` 里。全局那份写不进去（`AppData\Roaming\pip`
没有权限，报 WinError 5），所以只配了 venv 级的。

## 踩过的坑

| 坑 | 表现 | 怎么处理 |
|---|---|---|
| pip 装不上留垃圾 | 根目录多出 `pip-build-env-*`、`pip-install-*`、`pip-ephem-wheel-cache-*`，被提交进去了 | `.gitignore` 加了 `pip-*/` |
| 空仓库建不了 blob | `POST /git/blobs` 返回 409 Git Repository is empty | 先用 Contents API 写个 README 把对象库建起来 |
| 空仓库查 ref 返回 409 不是 404 | 按 404 写的容错没生效 | 两种都容忍 |

## 复现

```powershell
# 装依赖
.venv\Scripts\python.exe -m pip install -e ".[dev]"

# 跑测试
.venv\Scripts\python.exe -m pytest

# 推代码
.venv\Scripts\python.exe tools\push_to_github.py -m "提交信息"
```
