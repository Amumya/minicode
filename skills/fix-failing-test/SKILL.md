# 修失败的测试

按这个顺序走，别跳步：

1. **先跑一遍**，把失败的用例名和断言内容看清楚。
   Windows 上用 `python -m pytest -q`；只想看某个文件就加路径。
2. **读失败的断言**，弄清期望值和实际值差在哪。
3. **读被测代码**，找到产生实际值的那一行，不要只读报错附近。
4. **只改必要的地方**。测试文件不能改 —— 改测试等于改考题。
5. **重跑确认**，把通过输出贴出来。

要求：

- 不要用 `try/except` 把异常吞掉来"让测试过"
- 不要为了让某个断言成立而给函数加特判
- 如果发现是测试本身写错了，停下来，报告这个问题，不要自己改测试
