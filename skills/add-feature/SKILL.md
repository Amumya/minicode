# 加一个小功能

1. **先读现有代码**，尤其是同目录下已经写好的函数 —— 照着现有的风格来。
2. **找调用方**。要改的函数/类被谁用了？改接口会连带改谁？
3. **写代码**。只实现被要求的那一件事，不要顺手重构别的地方。
4. **补测试**：至少覆盖正常情况和一条边界（空输入、单元素、重复项之类）。
5. **跑全量测试**，不要只跑新加的那个。

几个常见的坑：

- 边界条件：空列表 / 空字符串 / None，往往就是隐藏测试要测的
- 类型：如果现有代码用 `list[int]` 这种注解，新代码也保持一致
- 中文和引号：写多行字符串时注意转义
